## What works

An explicitly approved autonomous source-collection watch owns a durable occurrence with a frozen contract, phase, dependency fingerprint, run budget and evidence references. Missing sources or owner input leave it waiting. Eligible evidence resumes the same occurrence; an edited watch or canonical research policy supersedes the old contract. A completed invocation is distinct from a verified occurrence.

The conversation loop recovers raw tool observations by run, suppresses equivalent repeated inspections, preserves passage versions/offsets and enforces the occurrence's tool budget. The existing model-call wrapper accounts request/token/cost usage; the existing capability gate authorizes tools. Verification checks required coverage and exact quotes against retained current source passages. The authoritative core service rechecks source revisions before committing occurrence truth and notification intent in one transaction.

Material-change delivery requires different explicit findings and different cited support compared with the prior verified result. Identical inputs skip the model; irrelevant new content can consume a bounded research turn without notifying. Delivery uses one existing outbox record independently of research. Ambiguous acknowledgements remain unknown; only explicit `DeliveryRejectedError` rejections are retried automatically.

|---|---|---|
| Missing dependency arrives in another required collection | Initial missing-evidence response uses 2 model calls; arrival causes 0 calls and leaves the question unanswered. | Initial response uses 2 calls; waiting uses 0; arrival uses 3 calls and verifies the same occurrence with no new steering prompt. |
| New content leaves the supported thesis unchanged | Initial answer uses 2 calls and 1 notification; unchanged tick uses 0; irrelevant addition uses 2 calls and sends another answer. | Same call counts; irrelevant addition sends 0 notifications. |

This demonstrates the control-flow connection hypothesized by H11. It does not establish model quality, statistical superiority, global novelty or a general Hermes/Nanobot failure. Raw JSON includes observation/run IDs and terminal statuses for inspection.

## Scope and limitations

- Opt-in indexed source-collection watches only. URL watches retain the existing behavior; network acquisition/indexing is separate. No new coding, trading, publishing or messaging authority is inferred.
- `verified` means the declared provenance/coverage contract passed. Exact quotes and current hashes do not prove semantic entailment, factual truth or complete prose-claim extraction. Subjects must be explicitly listed when their coverage is mandatory.
- Significance uses normalized explicit claim text plus cited support changes. It suppresses the demonstrated irrelevant addition but is not a calibrated semantic relevance classifier. Changes in assumptions/invalidation must appear in the supported claim.
- Dependency detection runs on scheduled ticks and watches configured required collections. It does not discover arbitrary external dependencies or wake instantly on a filesystem event. Owner input is explicitly targeted by watch ID.
- Ownership is single-host and fails closed while the recorded process is alive, including PID reuse. A dead worker can be reclaimed with a new token. A crash during a read before its observation is persisted can repeat that read; this slice authorizes no mutation tools. A crash during delivery remains unknown and requires reconciliation.
- Monetary usage uses existing configured pricing and post-response accounting. An explicit cap with missing pricing blocks the model. This is not a provider-enforced hard currency ceiling; a response can exceed the remaining amount and will stop further work. Requests include model requests and capability dispatches under Keli's existing counter semantics.
- Source tool observations are retained without the ordinary chat truncation on this path. Context is bounded; older source IDs/offsets remain addressable through `sources.read`. Existing archive/retention rules still apply.
- A failed occurrence does not silently obtain another budget on the same input. New approved contract/input is required; paused watches can be re-approved. No broad live-integration readiness claim follows from fixture tests.
